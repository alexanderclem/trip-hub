## Invariants

- Keep React 19, strict TypeScript, Vite/Router, current DaisyUI adaptations, Tailwind, Dexie, Zustand, MapLibre, Supabase, Vitest and Playwright. Add no aesthetic dependencies.
- Ordinary UI reads IndexedDB. Edits go through `save`/`saveMany`/`softDelete` and keep outbox/conflict/retry rules. Fixture seeding may write IndexedDB directly; product writes may not.
- No schema/RLS/production data changes, hard deletes, account gates, invite-token leaks, API/provider/agent/payment changes, pricing changes or paid infrastructure.
- Preserve all current URLs, query contracts, browser history, imported data and export formats. Native dialog and day-tab keyboard behavior remain.
- Preserve logos/Stowie master assets, Barlow fonts, semantic status colors and genuine trip status. No invented proof or synchronization success.
- Never reset unrelated working files or change other worktrees. Keep source changes reviewable; local commits only when conventions permit. Pushing main deploys Cloudflare, so do not push.

## Evidence and stopping rules

Capture the same fixture/clock/viewport before and after, inspect actual images, record commands/results and update stable findings. Do not call CSS zoom a physical-phone test. Do not use live Supabase suites merely to increase a pass count; the brief excludes live records. Failed or skipped coverage stays explicit. Resolve an affected task blocker before declaring an implementation phase passed.

Phase 01 has now bounded the research. The next pass should implement Phase 02, starting with the verified contrast defect; another broad inspiration or navigation audit is unnecessary.
